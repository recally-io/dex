# Glossary

This document defines the canonical domain terms of dex. Use one word for one concept within each boundary, and map explicitly across boundaries.

> **Status tags**: Each term is marked `current` (matches the code and UI today) or `target (Phase N)` (planned alignment; do not describe target behavior as current behavior in subsystem docs).

## Core objects (the 4 things a user learns first)

First, two foundational nouns used in scopes:

- **Owner** (`current`): The single person who owns the dex instance, all its bots, and its paired channels.
- **Project** (`current`): The working directory (`cwd`) selected for a session or automation, where tools run and `<cwd>/AGENTS.md` and project skills load.

| Term           | Status                                                       | Definition                                                                                                                                                                                                                                                                 | Scope                                 | Retire / avoid                                                                                                                                                  |
| -------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Bot**        | `current` (UI/tools), `target` (docs)                        | An AI assistant instance with its own model, instructions, memory, skills, default runner, channels, and automations.                                                                                                                                                      | Owner                                 | `Agent` in user-facing text (code keeps `internal/agent`, `/api/agents`, `agents` table; call Telegram credentials `Telegram Channel` or `Telegram bot token`). |
| **Session**    | `current`                                                    | A conversation and execution context of a bot. Kinds: `main` (shared by web and channels), `chat` (standalone), and `automation` (read-only transcript of an automation run). A **child session** is a `chat` session with a `parent_id` relation, not a separate kind.    | Bot                                   | `Conversation` (UI/docs), `Thread`, legacy background `Task` (`spawn_task`, `/tasks/<id>`, `/api/work`, `origin='task'`).                                       |
| **Task**       | `current` (single-bot), `target (Phase 3)` (multi-bot links) | A Jira-style work item with a title, status, timeline, and external object links (such as a GitHub PR or email thread). A Task keeps an **owner bot** (which receives `Send to Main` and external alerts) and, in Phase 3, can link sessions across bots as collaborators. | Owner (global view), owned by one Bot | `WorkTask` in user-facing text.                                                                                                                                 |
| **Automation** | `current` (tools), `target` (UI)                             | A persistent, recurring schedule rule and its run history. An automation runs on a schedule in its own session or in a bound session, and requires an explicit outcome report.                                                                                             | Bot                                   | `Routine` (`*_routine`, `report_check`); do not expose `Scheduler` as a user concept.                                                                           |

## Views (projections, not independent entities)

| View      | Status    | Definition                                                                                                                                                                                                                                                                                    | Notes                                                                                                                                                                                                          |
| --------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Board** | `current` | The global list and board view of all **Tasks** across bots.                                                                                                                                                                                                                                  | Replaces mixing Tasks into `/inbox`. Creating a view does not change Task ownership or permissions.                                                                                                            |
| **Inbox** | `current` | The owner's unified attention stream. Every Inbox item has an explicit owner resolve action: active unanswered `ask_user` questions (answer), unhandled failed or changed Automation results (handle), Automations missing a model (configure), and held external events (attach or dismiss). | Replaces the `Needs you` list. Queued Task questions remain in Task detail until they become active. One-way `notify_user` messages have no resolve action and stay in chat transcripts / channels, not Inbox. |

## Session features (scoped inside one Session)

| Feature     | Status                           | Definition                                                                                                                                                                                                                                                                                              | Notes                                                                                                                                                                                                                                 |
| ----------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Monitor** | `current`                        | A short-lived, bounded schedule or script-polling check attached to one session (one-shot delay or up to 7 days / 100 runs, optional `checkCommand` SHA-256 check). It wakes its session and ends automatically without entering Inbox.                                                                 | Keeps the `Monitor` name exclusively for schedule/check (`monitors` table). Replaces `Followup Timer`.                                                                                                                                |
| **Process** | `current` (tools), `target` (UI) | A long-running background shell command started via `process_start` (with `wake: exit \| lines \| none`) and managed via `process_list` / `process_stop`. Bound to its session (`background_commands` table); stops with session cancellation, not Main foreground Stop; shows `unknown` after a crash. | Separated from `Monitor` and kept outside PiG's built-in `bash` tool so engine/business boundaries, schemas, and replay semantics stay clean. Monitor and Process share the session's active cap (32) and wake chain depth limit (6). |
| **Files**   | `current`                        | Two directional concepts: **Attachment** (mutable file or image sent by the owner to a session) and **Artifact** (immutable snapshot delivered by a bot via `deliver_file`).                                                                                                                            | Use `Artifact` instead of `Delivery`; keep `Upload` internal to HTTP/storage.                                                                                                                                                         |

## Setup and connections

| Term           | Status                                    | Definition                                                                                                                                                                                                                                                                       | Scope                                                | Notes                                                                                                                                                                                                                                                                                     |
| -------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Runner**     | `target (Phase 1)` (`Environment` today)  | Where tools and commands execute. Types: `Local` (this host), `SSH` (remote SSH host), `Sandbox` (container such as E2B), and `Remote` (a remote host running `dex-agent`).                                                                                                      | Owner (global), bound by Bot, Session, or Automation | Changing a Runner changes which machine receives resolved secrets. `execenv.KindRunner` is the stored `runner` kind and displays as `Remote`. The `background.executor` interface runs Process commands. Do not rename the `dex-agent` binary without a dedicated release migration plan. |
| **Secrets**    | `target (Phase 1)`                        | Credential configuration separated from Runner pages: encrypted **Vault** secrets (global shared and bot-level overrides, resolved and masked on the control host) and **1Password** credential forwarding (evaluated by `op read` on the runner; dex does not mask its output). | Owner (global) + Bot                                 | Current tool name: `secret_list`. Note that some channel, provider, and source credentials currently remain plaintext in `control.sqlite` (see [Security](architecture.md#security)).                                                                                                     |
| **Skills**     | `current`                                 | Reusable Markdown instructions, workflows, and helper scripts in the bot knowledge layer alongside instructions and memory. Skills may reference secret names (`vault:NAME`) but never store secret values.                                                                      | Global, Bot, or Project                              | Lift out of the retired `Extensions` / `Tools` wrapper.                                                                                                                                                                                                                                   |
| **Channel**    | `current`                                 | Owner chat entry point (`Telegram`, `WeChat`, `Feishu / Lark`). Produces owner-authorized session inputs and receives outbound replies.                                                                                                                                          | Bot                                                  | Grouped under the `Integrations` UI section, but remains a distinct domain concept.                                                                                                                                                                                                       |
| **MCP Server** | `current`                                 | Outbound external tool server loaded via `.agents/` declarations and applied on agent Reload.                                                                                                                                                                                    | Global or Bot                                        | Grouped under `Integrations` in UI; shares reload lifecycle with Skills.                                                                                                                                                                                                                  |
| **Source**     | `target (Phase 1)` (`Plugin` in UI today) | Inbound external event feed (`GitHub`, `Webhook`, `Email`) that creates or updates Board Tasks under trust rules and applies on server restart.                                                                                                                                  | Owner (global)                                       | Grouped under `Integrations` in UI. Keep **Plugin** as the internal term for a Source's modular implementation.                                                                                                                                                                           |

> **UI grouping (`Integrations`)**: `Integrations` is a navigation label only (covering Channels, MCP Servers, and Sources), not a unified runtime abstraction. Retire `Extensions` and user-facing `Plugins`.

## Internal architecture terms (engineering docs and code only)

| Term                  | Definition                                                                                                                                | Notes                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Submission**        | One durable inbound input intent in `control.sqlite` (`submissions`).                                                                     | Refer to this table as the **Input Queue**, not `Inbox` or `Receipt`.                                         |
| **Automation run**    | One business record in `automation_runs` (can settle as `changed`, `unchanged`, `failed`, or `skipped` without ever invoking the engine). | Distinct from a PiG **Run**.                                                                                  |
| **Run / native task** | One PiG engine execution pass (`native task` in engine code and Stop APIs).                                                               | Keep PiG's `task` naming inside `internal/engine`; write `native task` when disambiguating from Board `Task`. |
| **native Inbox**      | PiG's durable per-conversation queued input store inside `agents/<id>/state.sqlite`.                                                      | Always qualify with `native` so it never collides with UI `Inbox`.                                            |
| **Outbox**            | Durable outbound channel delivery queue (`outbox_messages`, `outbox_files`).                                                              | Channel delivery only; explicit web notices use `web_notifications`.                                          |
| **Webhook Queue**     | Durable inbound channel webhook buffer (`channel_webhook_inbox`).                                                                         | Call it a queue, not an inbox.                                                                                |
| **Scheduler**         | The `internal/scheduler` ticker loop that triggers periodic checks for Automations, Monitors, and Dreams.                                 | Infrastructure only.                                                                                          |
| **Plugin**            | Optional modular backend unit (`internal/plugin`, `plugin_<name>_*` tables, `enabled_plugins`) implementing a **Source**.                 | Retained internally; do not retire in code.                                                                   |
| **Dream**             | Hidden periodic memory-consolidation session (`dreams` table).                                                                            | Not visible in user session lists or `session_*` tools.                                                       |

## Navigation alignment (target)

- **Global navigation**: `Bots`, `Board` (Tasks), `Inbox` (attention stream), and global `Settings` (`General`, `Providers`, `Runners`, `Secrets`, `Integrations`, `Archived`, `About`).
- **Bot workspace**: `Sessions`, `Automations`, and Bot `Settings` (`General`, `Skills`, `Integrations`, `Secrets`).

## Rollout phases and non-goals

1. **Phase 1 — Glossary, UI labels, and view split**: Board and Inbox are separate views. The split does not change Task ownership, tools, or schemas. Align the remaining UI labels (`Automations`, `Runners`, `Secrets`, `Skills`, `Integrations`).
2. **Phase 2 — Agent tools**: `automation_*`, `secret_list`, `monitor_*`, and `process_*` are current. Pending PiG calls under retired names cannot resume after an upgrade. Committed changes stay saved. Task alerts keep the `task_result` kind.
3. **Phase 3 — Multi-bot Task collaboration**: Extend `Task` with multi-session cross-bot links while retaining a single owner bot for `Send to Main` and alert routing, with explicit cross-bot read/write permission rules and a dedicated schema migration.
4. **Non-goals (won't do)**: Do not rename existing SQLite tables (`agents`, `conversations`, `execution_environments`, `work_tasks`), Go packages, or the `dex-agent` binary solely for naming symmetry. Maintain one meaning per boundary and use this table to map across boundaries.
