# Bot 工具与连接验收场景

只在验收专用的临时 Dex 上运行。不要连接真实渠道，不要输入真实凭据。

1. 给定一个 Bot，且存在 Dex 共享 Skill 和 Bot 同名 Skill。打开「工具与连接」。应只列出有效的同名 Skill，并标明其来源和覆盖关系。页面独立显示 MCP 状态、Telegram、飞书和微信。没有 Skill 或 MCP 的 Bot 应显示空态，仍可刷新。
2. 给定空闲的 Bot，点击「重载工具」。操作完成前不能再次发起重载。成功后显示最新的 Skill 和 MCP 状态。如果有执行尚未完成，重载失败后保留已有列表，并可重试。
3. 给定有已启用渠道的验收数据，点击对应渠道的「断开…」。先取消，状态不变。随后确认断开，页面应重新读取状态并显示「未启用」。没有可用的已配置渠道时，不显示断开按钮。
4. 使用 `NSGO_CHECK` 和非凭据字符串 `local-only-probe` 验证 Bot 密钥。新建后列表只显示名称和更新时间。打开替换表单，值为空；提交后列表更新，值不出现在状态或列表中。取消删除不改变列表；确认删除后该项消失。Dex 共享密钥不会出现在此列表。
5. 给定请求失败，相关分区指出失败并提供刷新或重试。其它分区保持可用。切换 Bot 时，之前 Bot 的结果不得出现在新页面。
